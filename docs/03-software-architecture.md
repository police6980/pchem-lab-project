# 03. 소프트웨어 아키텍처

**문서 목적**: 전체 소프트웨어 구조, 모듈 간 역할 분담, 데이터 흐름을 정의한다.

---

## 전체 구조 개요

```
[아두이노/ESP32] 
    ↓ (USB, 시리얼 통신)
[Web Serial API]
    ↓ (JavaScript 이벤트 스트림)
[웹 애플리케이션]
    ├─ 시뮬레이션 엔진 (p5.js)
    ├─ UI 컨트롤
    ├─ 데이터 로거 (CSV)
    └─ LLM 통신 모듈
         ↓ (HTTPS API)
    [외부 LLM API]
```

## 핵심 원칙

1. **계층 분리**: 센서 → 통신 → 시뮬레이션 → 표시 각 계층을 명확히 분리.
2. **공통 코어 + 실험별 모듈**: 보일, 샤를, (향후) 산염기 실험이 같은 엔진을 공유.
3. **설정 파일 기반**: 튜닝 가능한 상수(수렴 속도, 입자 수 등)는 설정 파일로 분리해 코드 수정 없이 조정.
4. **확장성**: 새 실험·센서 추가가 쉬운 구조.

## 애플리케이션 진입 구조

### 선택 화면 (엔트리 포인트)

앱 실행 시 가장 먼저 보여지는 화면:

- **실험 선택 메뉴**:
  - 보일 법칙 실험
  - 샤를 법칙 실험
  - (추후) 산염기 실험들
- 선택 시 해당 모드로 진입, 관련 UI·센서 설정 로드

### 독립 실행 구조

각 실험은 독립된 페이지 또는 독립 앱 형태로 동작. 공통 엔진은 공유하지만 런타임에 서로 간섭하지 않음.

## 모듈 구성

### 1. 펌웨어 계층 (아두이노/ESP32)

**역할**: 센서 원시값 읽기, 간단한 전처리, 시리얼 포트로 JSON 송출.

**책임**:
- 각 센서 초기화
- 지정 주기로 값 읽기 (pH: 500ms, 온도: 1s, 압력: 200ms)
- 이동 평균 스무딩 (버퍼 크기 설정 가능)
- 표준 JSON 포맷으로 시리얼 출력

**출력 포맷 예시**:
```json
{"sensor": "pressure", "value": 103.5, "unit": "kPa", "timestamp": 12345}
```

세부는 `05-data-format.md` 참고.

### 2. Web Serial 통신 계층

**역할**: 브라우저에서 아두이노와 시리얼 통신.

**책임**:
- 사용자가 포트 선택 (Web Serial API 권한 요청)
- 데이터 수신 스트림 관리
- JSON 파싱 및 유효성 검증
- 이벤트 기반 구독 시스템 (여러 모듈이 같은 데이터를 구독 가능)

**기술 스택**: Web Serial API (Chrome/Edge 브라우저 필요, HTTPS 또는 localhost)

### 3. 시뮬레이션 엔진

**역할**: 입자 시뮬레이션 실행, 물리 규칙 적용, 렌더링.

**핵심 클래스**:

- `Particle`: 단일 입자. 위치, 속도, 종류, 색상.
- `ParticleSystem`: 입자 컨테이너. `update(dt)` 메서드로 매 프레임 상태 갱신.
- `Renderer`: p5.js 캔버스에 렌더링. 로직과 시각화 분리.
- `ExperimentMode`: 실험별 특수 로직 (보일/샤를/산염기).

**물리 규칙**: `04-simulation-physics.md` 참고.

### 4. UI 컨트롤

**역할**: 학생 상호작용 UI.

**주요 컴포넌트**:
- 실험 선택 화면
- 초기값 설정 패널 (센서값 자동 제안 + 학생 확인)
- 실시간 센서값 표시
- 시뮬레이션 캔버스
- "예측 vs 실측" 비교 패널
- AI 튜터 대화창
- 데이터 기록 시작/종료 버튼

**기술 스택**: HTML + CSS + Vanilla JS (또는 필요 시 경량 프레임워크)

### 5. 데이터 로거

**역할**: 실험 데이터를 CSV 파일로 저장.

**책임**:
- 센서값 타임스탬프와 함께 기록
- 학생 조작 이벤트 기록
- AI 튜터 대화 로그
- 실험 종료 시 CSV 파일 다운로드 제공

세부 포맷은 `05-data-format.md` 참고.

### 6. LLM 통신 모듈

**역할**: 생성형 AI API 호출, 비동기 응답 처리.

**책임**:
- 실험 상태를 JSON 컨텍스트로 구성
- API 호출 (비동기)
- 응답 파싱 및 UI 표시
- 로딩 UX 처리 (1~3초 지연 동안 내러티브 텍스트 스트리밍)

**트리거 조건**: 
- 학생 직접 질문
- 이벤트 기반 (특정 조건 충족 시 자동 질문 제안)

세부 설계는 추후 `llm-tutor.md` 문서에서 확정.

## 데이터 흐름

### 일반적인 실험 사이클

```
1. 사용자가 실험 선택 → 모드 진입
2. Web Serial 포트 연결
3. 초기값 설정 (센서값 자동 제안)
4. "시작" 버튼 → 실험 루프 시작
5. 매 프레임 (60Hz):
   a. 시리얼에서 최신 센서값 수신
   b. 시뮬레이션 엔진 업데이트
   c. UI 갱신 (그래프, 수치, 비교 패널)
   d. 로거에 데이터 기록
6. 특정 이벤트 발생 시:
   - LLM 호출 (비동기)
   - 응답 수신 시 AI 튜터 창에 표시
7. 실험 종료:
   - CSV 파일 다운로드 제공
   - 요약 리포트 생성 (LLM 호출)
```

## 기술 스택 결정

| 계층 | 기술 | 결정 사유 |
|---|---|---|
| 펌웨어 | Arduino C++ | 표준, 레퍼런스 풍부 |
| 통신 | Web Serial API | 별도 설치 없이 브라우저에서 직접 통신 |
| 시뮬레이션 | p5.js | 교육용 레퍼런스 풍부, 빠른 프로토타이핑 |
| UI | HTML/CSS/Vanilla JS | 단순함 우선, 프레임워크 없이도 충분 |
| 로깅 | Browser Storage → CSV | 로컬 처리, 프라이버시 안전 |
| LLM | Anthropic Claude API (또는 OpenAI) | 미정, LLM 문서에서 결정 |

## 폴더 구조 (소프트웨어)

```
pchem-lab-project/
├── firmware/
│   ├── common/              (공통 유틸, 스무딩, JSON 출력)
│   ├── boyle/               (보일 실험용 펌웨어)
│   ├── charles/             (샤를 실험용 펌웨어)
│   └── acidbase/            (산염기 - 추후)
├── web/
│   ├── index.html           (선택 화면)
│   ├── experiments/
│   │   ├── boyle/
│   │   ├── charles/
│   │   └── acidbase/        (추후)
│   ├── engine/              (시뮬레이션 엔진 공통)
│   │   ├── particle.js
│   │   ├── particle-system.js
│   │   ├── renderer.js
│   │   └── physics-rules.js
│   ├── serial/              (Web Serial 래퍼)
│   ├── ui/                  (UI 컴포넌트)
│   ├── logger/              (CSV 로거)
│   ├── llm/                 (LLM 통신)
│   ├── config/              (설정 파일들)
│   │   ├── simulation.json
│   │   └── experiments.json
│   └── assets/              (이미지, 폰트 등)
```

## 설정 파일 (simulation.json 예시)

```json
{
  "particle": {
    "default_count": 250,
    "render_radius": 4,
    "velocity_distribution": "maxwell-boltzmann"
  },
  "convergence": {
    "volume_tau_seconds": 0.5,
    "velocity_tau_seconds": 0.05
  },
  "smoothing": {
    "pressure_window_size": 5,
    "temperature_window_size": 10
  }
}
```

이 값들은 실행 중 실시간 수정 가능하게 만들어서 튜닝 편의성 확보.
