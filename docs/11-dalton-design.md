## 1. 실험 개요

### 1.1 교육 목표

고등학교 영재 과학교육용으로 **돌턴의 부분압력 법칙**을 체험시키되, 보일 법칙을
자연스럽게 병행 학습. **주사기 A(능동)** 의 기체를 **주사기 B(수용, 피스톤 고정)**
로 밀어넣으며:

1. **주사기 A 내부**: 피스톤 하강 → 부피 감소 → 압력 증가 (**보일 법칙**)
2. **주사기 B (초기 상태)**: 기체 B가 대기압 1 atm 으로 V_B 차지 → P_initial 센서 측정
3. **주사기 B (주입 완료 후)**: A의 기체가 V_A → V_B 공간에 팽창 합류 → P_total 측정
4. **돌턴 법칙 검증**: `P_total = (V_A/V_B + 1) × 1 atm` 이론값과 실측 비교
5. **실측/시뮬/이론 3값 비교**: 오차 원인 탐구, 과학적 사고 배양

### 1.2 핵심 학습 흐름

```
단계 0  실험 조건 설정 (기체 A·B 종류, V_A 부피, V_B 프리셋 선택)
   ↓
단계 1  [초기 측정]
        주사기 A·B 모두 대기압 상태 (A·B 둘 다 1 atm)
        센서(주사기 B에 연결) 표시: P_initial = 1.00 atm
        UI: 주사기 A 압력란 = 1.00 atm (센서값 복사)
   ↓
단계 2  AI 튜터: "A, B의 초기 압력을 예측해봐. 같을까 다를까?"
        학생: 대기에서 뽑았으니 둘 다 1 atm
   ↓
단계 3  [주입 시작] → 피스톤 애니메이션 3초
        주사기 A의 기체가 V_A → V_B 공간으로 이동
        주사기 A는 비어짐, 주사기 B의 기체 증가
   ↓
단계 4  안정화 5초 카운트다운 → 센서 안정값 확보
        주사기 A 압력: "—" 비표시 (기체 없음)
        주사기 B 압력: 센서 실측값 (예: 2.00 atm)
   ↓
단계 5  [확인] 버튼 → 현재 측정값을 기록 테이블에 저장
        이론값 (V_A/V_B + 1) × 1 atm 과 비교
        AI 튜터: "왜 이 값이 나왔는지 돌턴 법칙으로 설명해봐"
   ↓
단계 6  [초기화] 후 V_A 변경하며 반복 실험
   ↓
단계 7  CSV 내보내기 + 보고서 생성
```

### 1.3 실험실 현실과의 매칭

- **주사기 A·B 초기 압력 = 대기압 1 atm 동일**. 둘 다 대기에서 채취, 자연히 같은
  압력. 센서는 주사기 B에만 부착되므로 A의 초기 압력은 **센서값을 그대로 복사**
  표시 (물리적으로 같으므로 정확)
- **주사기 A·B 부피 = 숫자 입력 전용** (범위 10~100mL, 1mL 단위, 기본값 50mL).
  슬라이더 없음. 학생은 숫자 박스에 직접 타이핑, Enter 또는 blur 시 clamp 후 반영.
  - A·B 범위 통일 이유: UI 인지 부담 감소, 실험실의 보편적 소형 주사기 범위와 일치
  - 실험 시작 후 주사기 B 입력 필드 **비활성화**, 피스톤은 클램프·스토퍼로 **고정** 상태 유지
  - 이론상 P_total 최대 = (100/10 + 1) × 1atm = 11atm (V_A=100, V_B=10). 실센서
    DFRobot 1.6MPa(약 15.8atm) 측정 범위 내. 교사는 극단 시나리오 시 학생 안전
    안내 필요
- **주입 모델 = A→B 일방향 완전 주입**. A·B 사이 체크밸브로 역류 방지. A 피스톤
  끝까지 밀어 A의 모든 기체를 B로 이동. 주입 후 A는 비어있음 → UI에서 A 압력
  비표시 (의미 없는 값 표시 방지)

## 2. 결정 기록 (논문 1차 자료)

결정 번호 표기 규칙: 번호는 의사결정이 내려진 시간 순서 기준. 문서 내 위치는
논리 그룹화에 따라 재배열될 수 있음 (예: 결정 6·7은 결정 4 직후에 위치하나, 결정 5는
마지막에 배치). 이력 보존 원칙에 따라 번호는 재부여하지 않음.

아래 7개 결정은 심화 검토·모델 전환을 거쳐 확정. 논문 방법론 섹션 1차 자료로 보존.

### 결정 1: 주사기 2개 + 중앙 용기 모델 채택

**배경**: 돌턴 법칙 시연에는 2종 기체 혼합이 필수. 구성 방식 여러 가지.

**결정**: 각각 다른 기체를 담은 주사기 2개 → 고정 부피 용기로 순차 주입.

**근거**:
- 주사기는 고등학교 실험실 흔하고 안전
- 피스톤 조작이 직관적 → "부피 감소 = 압력 증가" 체감
- CO₂ 캡슐·탄산 반응 등 기체 생성법과 호환
- **보일·돌턴 법칙을 한 실험에서 병행 학습** 가능

**배제된 대안**:
- CO₂ 센서 추가: SCD41(5000ppm) 포화, 캡슐 환경 부적합. 하드웨어 복잡도 증가 대비 득 적음
- "추가/제거" 버튼: 특정 기체 제거는 물리적으로 불가능 → 시뮬-실센서 괴리
- 단일 용기 + 순차 주입 없이 모드만 전환: 초기 조건 센서 측정 의미 약화

### 결정 2: 주사기 초기 압력 = 대기압 1 atm 고정

**배경**: 초기 설계에서 주사기 압력 슬라이더 제공. 그러나 실험실 현실과 모순.

**결정**: 주사기 초기 압력은 **항상 1 atm**. UI에 슬라이더 제공 안 함. 학생이 조절하는
변수는 **주사기 부피**(기체 양)뿐.

**근거**:
- 고등학교 실험실에서 2.5 atm 같은 비대기 기체를 주사기에 정량 담는 방법 없음
- 돌턴 법칙 검증에는 부피 하나만 변수여도 충분 (공식: `P_A^(혼합) = P_A_init × V_A / V_fixed`)
- UI 단순화 → 학생이 의미 있는 변수만 조작
- **실험-시뮬 매칭도 향상**: 실물에서 "주사기는 대기에서 뽑음" → 시뮬도 동일 전제

**배제된 대안**:
- 슬라이더 유지: 현실 괴리, 학생이 "왜 이 값을 고르지?" 의문
- 프리셋 3단 (0.5/1.0/2.0 atm): 여전히 0.5, 2.0의 물리적 의미 불명

### 결정 3: 순차 주입을 기본 동작으로

**배경**: 초기 설계는 "A·B 동시 주입" 기본. 교육적 흐름 재검토 필요.

**결정**: `[A 주입]` → 측정 → `[B 주입]` → 측정 순서. 별도 토글 없음.

**근거**:
- 돌턴 법칙 학습의 최적 흐름: "단독 관찰 → 합산 관찰 → 차이 유도 → 법칙 검증"
- 동시 주입은 이미 합쳐진 결과만 제공 → "왜 수식이 성립하는지" 직관 약함
- AI 튜터 Q1~Q4가 **주입 단계와 동기화** 가능:
  - Q1 (A 주입 후): "P_A^(혼합)을 관찰·계산"
  - Q2 (B 주입 전): "P_total 예측"
  - Q3 (B 주입 후): "예측과 실측 비교, 원리 탐구"
  - Q4: 실생활 응용

**배제된 대안**:
- 동시 주입: 교육 효과 감소
- 사용자 토글: UI 복잡도 증가, 초보 학생 혼란

### 결정 4: 실센서 센서 1개 유지 (주사기 B에만)

**배경**: 주사기 2개에 각각 센서 붙이면 총 3개. 프로토콜·하드웨어·비용 증가.

**결정**: 실센서는 **주사기 B (수용기) P 하나만**. 주사기 A 압력은 B 센서값을 복사
(주입 전 대기압 동일 가정), 주입 후 비표시.

**근거**:
- 주사기 A·B 초기 압력은 대기에서 채취하므로 자연히 동일 → A 센서 불필요
- 주사기 A는 주입 후 비어있음 → 사후 압력 측정 의미 없음
- 주사기 B 센서 하나로 "초기 P_B = P_A" + "주입 후 P_total" 모두 확보
- 기존 DFRobot Gravity 1.6MPa + WS v1.1 프로토콜 그대로 재활용
- 하드웨어 비용·수업 관리 부담 최소

**배제된 대안**:
- 센서 2개 (A·B 각각): A 센서는 항상 B와 동일값·주입 후 의미 없음 → 잉여
- 센서 3개 (A·B·중앙 용기): 이전 설계 잔재, 아래 결정 6에 의해 중앙 용기 제거됨
- 센서 0개 (시뮬만): CAST의 MBL 통합 정체성 훼손

### 결정 6: 3영역(A·중앙 용기·B) → 2영역(A·B) 모델 전환

**배경**: 초기 설계는 주사기 A·B 가 중앙 밀봉 용기로 주입하는 3영역 모델. 심화 검토
후 하드웨어 복잡도, 조립 난이도, 비용 재평가.

**결정**: **주사기 A(능동) → 주사기 B(수용, 피스톤 고정)** 2영역 모델 채택. 중앙 용기
DOM·시뮬·하드웨어 전면 제거.

**근거**:
- 하드웨어 단순화: T자 분기관 + 밀봉 용기 제거 → 주사기 2개 + 체크밸브 연결관만
- 조립 용이: 직선 연결, 누설 포인트 감소
- 비용 절감: 세트당 3만원 → 1.5~2만원 (약 50%)
- 시뮬 단순: 3분할 렌더 → 2분할
- 교육적 본질 유지: "A의 기체가 B로 이동·합류 → 압력 증가" 서사 성립
- 돌턴 법칙 수식 동일하게 성립: `P_total = (V_A/V_B + 1) × 1 atm`

**배제된 대안**:
- 중앙 용기 유지: 하드웨어·비용 부담, 조립 실수 지점 많음
- 주사기 B 피스톤도 움직임 허용: 변수 증가, 교육 집중도 저하
- 주사기 3개 이상: 확장성은 높으나 범위 과대

**주의사항**:
- 주사기 B는 **피스톤 고정 메커니즘** 필수 (클램프·스토퍼 또는 O-ring 마찰).
  학생이 UI에서 설정한 V_B 값(10~100mL)에 맞춰 실물 피스톤도 해당 눈금에서 고정.
  고정 위치가 연속적이어야 하므로 단순 스토퍼보다 **나사식 클램프** 권장.
- 주사기 B는 **투명한 것** 권장 (혼합 시각화 유지). A·B 범위가 10~100mL 로
  통일됐으므로 동일 규격 소형 주사기 사용 가능 (조달·관리 단순화)
- A→B 사이 **체크밸브 필수** (없으면 돌턴 법칙 교육 효과 약화, 단순 보일 법칙으로 축소)
- 이론 P_total 최대값 점검: V_A=100, V_B=10 시 11atm. 실물 주사기·밀봉부 내압
  한계 확인 필수. 학급 시연 시 V_B 최소 20mL 권장 (P_total 최대 6atm 이내)

### 결정 7: 주사기 A 압력 표시 정책 — 복사 + 사후 비표시

**배경**: 결정 4에 따라 주사기 A에는 센서 없음. UI에서 A의 압력을 어떻게 표시할지
결정 필요.

**결정**:
- **주입 전**: 주사기 A 압력 = 주사기 B 센서값 그대로 복사 표시
- **주입 후**: 주사기 A 압력 = "—" 비표시 (기체 없음, 의미 없는 값 표시 방지)

**근거**:
- 주입 전 A·B 둘 다 대기압 → 물리적으로 동일 → 복사해도 정확
- 학생이 "같은 대기에서 뽑은 두 기체의 압력이 같다"를 직관적으로 이해
- 주입 후 A는 비어있음 → 0 atm 표시보다 "—" 비표시가 덜 혼란스럽고 정확
- 시뮬 모드에서도 동일 규칙 적용 (일관성)

**배제된 대안**:
- A 압력을 고정 상수 "1.00 atm" 표시: 실험실 대기압이 정확히 1 atm 아닐 수 있음 (해발·날씨 차이). 센서값 복사가 더 정확
- A 압력 센서 추가: 결정 4 위배, 비용 증가
- 주입 후 A 압력을 0 atm 표시: 학생이 "진공?" 오해 가능. "—" 비표시가 명료

### 결정 5: Phase 5 범위는 시뮬 + 프로토타입 1세트

**배경**: 돌턴 실험용 하드웨어는 Phase 3 보일 실험과 다름(주사기 + T분기 + 밀봉 용기).
학급용 전체 조달하면 Phase 5 기간 과대.

**결정**: Phase 5에서는 **시뮬 완성 + 프로토타입 하드웨어 1세트** 제작. 학급용 다수
제작은 Phase 6으로 이연.

**근거**:
- Phase 5의 핵심은 **교육 콘텐츠 설계**와 시뮬레이션
- 프로토타입 1세트로 실센서 연동·검증 가능 (교사 시연용)
- 학급 조별 하드웨어는 재료비·조립 시간 고려하면 별도 Phase 필요

**배제된 대안**:
- 전체 하드웨어 포함: Phase 5 기간 2배 이상
- 하드웨어 0 (시뮬만): MBL 실험 정체성 약화

### 4.2 좌측 설정 패널 상세

**주사기 A 섹션 (능동)** (`<section id="dalton-syringe-a">`)
- 기체 종류 select: 공기 / CO₂ / He / N₂ / O₂ (5종), 기본 공기
- 부피 V_A: **숫자 입력 전용** (`<input type="number">` id `dalton-volume-a-number`)
  - 범위 10~100mL, 1mL 단위, 기본 50mL
  - Enter 또는 blur 시 clamp 후 상태 반영 (타이핑 중 즉시 반영 안 함)
  - 범위 밖 값: 10·100 경계로 clamp
  - 잘못된 값(NaN 등): 직전 상태값 복구
- 압력 표시 (동적):
  - 주입 전: "P_A = {센서값} atm (B와 동일)" — 주사기 B 센서값 복사
  - 주입 중: "주입 중..." 비활성
  - 주입 후: "P_A = — (비어있음)" 비표시
- 입자 수 자동 계산: `N = k × (1.0 × V_A)` (k는 시뮬 스케일 상수)

**주사기 B 섹션 (수용, 피스톤 고정)** (`<section id="dalton-syringe-b">`)
- 기체 종류 select: 공기 / CO₂ / He / N₂ / O₂ (5종), 기본 CO₂
- 부피 V_B: **숫자 입력 전용** (`<input type="number">` id `dalton-volume-b-number`)
  - 범위 10~100mL, 1mL 단위, 기본 50mL (주사기 A 와 통일)
  - Enter 또는 blur 시 clamp 후 상태 반영
  - 범위 밖 값: 10·100 경계로 clamp
  - 잘못된 값(NaN 등): 직전 상태값 복구
- 주입 시작 후 숫자 박스 `disabled`
- 압력 표시: 센서 실측값 (실센서 모드) 또는 시뮬 계산값 (시뮬 모드)
- 피스톤 고정 안내: "피스톤 고정 — 실험 중 부피 불변"

**입력 방식 통일 근거**:
- 주사기 A (능동) 는 여러 값으로 탐색하는 기체이나, 슬라이더 드래그로 정확한 값
  맞추기 어려움 → 숫자 입력이 오히려 탐색 효율적
- 주사기 B (수용) 는 한 번 설정 후 고정되므로 숫자 입력으로 충분
- A·B 통일 UI 로 학생 인지 부담 감소
- 프리셋 힌트 제거로 시각적 단순화

**이론값 박스** (실시간 계산)
- 주입 전: 1.00 atm (= 대기압)
- 주입 후: `(V_A/V_B + 1) × 1.00 atm` (예: V_A=100, V_B=100 → 2.00 atm)
- V_A, V_B 변경 시 즉시 갱신

**제어 버튼 (3개)**
- `[주입 시작]`: `IDLE` 상태에서만 활성. 클릭 시 피스톤 애니메이션 3초.
  완료 후 `INJECTED` 상태, 안정화 카운트다운 5초 자동 시작
- `[확인]`: 안정화 완료 후 활성. 클릭 시 현재 측정값을 기록 테이블에 추가 후 `CONFIRMED` 상태.
  `CONFIRMED` 상태에서 `[초기화]` 해야 다음 실험 가능
- `[초기화]`: 언제든 활성. `IDLE` 복귀, 주사기 A 기체 재생성, 주사기 B 초기 상태 복원

## 5. 시뮬레이션 물리 설계

### 5.1 주입 물리 모델: A→B 일방향 완전 주입

- **가정**: 주사기 A→B 사이 체크밸브가 있어 기체는 B 방향으로만 이동, 역류 없음
- **피스톤 A 끝까지 이동**: 주사기 A 내 모든 기체(n_A 몰)가 주사기 B 로 이동
- **주사기 B 피스톤 고정**: V_B 는 실험 중 불변
- 주입 후 주사기 A 는 비어있음 (피스톤이 바닥)
- 주사기 B 내 부분압력 (돌턴 법칙):
  - `P_A^(in B) = (1 atm × V_A) / V_B` — A 기체가 V_A → V_B 공간 팽창
  - `P_B^(in B) = 1 atm` — B 기체는 원래 V_B 에 1 atm, 부피 불변이므로 그대로
  - `P_total = P_A^(in B) + P_B^(in B) = (V_A/V_B + 1) × 1 atm`
- **UI 안내**: "A 피스톤을 끝까지 밀어 모든 기체를 B로 이동시킵니다. B 피스톤은 고정됩니다." 문구 표시
- AI 튜터 심화: "만약 A 피스톤을 부분적으로만 밀면 어떻게 될까?", "만약 B 피스톤이 고정 안 된다면?" Q 제공

### 5.2 입자 상태 머신

```
IN_SYRINGE_A       주사기 A 내부, 실린더 벽 경계 (주입 전 기체 A)
IN_SYRINGE_B_ORIGINAL   주사기 B 내부, 실험 시작 시부터 존재하는 기체 B
TRANSIT_A_TO_B     A→B 이동 중 (체크밸브 경로)
IN_SYRINGE_B_MIXED  주사기 B 내부, A에서 넘어온 입자 (색상은 type 유지)
```

입자 객체:
```js
{
  type: 'A' | 'B',
  state: 'IN_SYRINGE_A' | ... ,
  x, y, vx, vy,
  radius, mass,           // 기체별 프리셋 (§5.6)
  baseSpeed,              // 분자량 기반 맥스웰-볼츠만 평균 속도
  color                   // 기체별 HEX
}
```

### 5.3 주사기 내 물리

- 실린더 박스 경계: `(left, top, right, bottom)` 
- 피스톤 위치 `piston_x`: 초기 부피에 비례, 주입 시 점진 이동
- 피스톤 하강 시 입자는 피스톤 벽과도 충돌 처리 (보일 법칙 체감)
- 주사기 내 압력 게이지:
  - `P_syringe = k × hits_per_sec / A_internal_wall`
  - 슬라이더 변경에 맞춰 이론값 1 atm 근방에서 안정
  - 부피 축소 시 증가 (보일 법칙 시각화)

### 5.4 주사기 B 물리 (수용기)

- 기존 `Box` 클래스 재활용, V_B 크기의 직사각형 경계
- 벽 충돌 시 `type` 별 카운터 증가: `hits_A`, `hits_B`
- 250ms tick마다:
  - `P_A_sim = k × hits_A / Δt` (EMA α=0.15 적용) — A 기체가 B에서 내는 부분압력
  - `P_B_sim = k × hits_B / Δt` — B 기체가 내는 부분압력
  - `P_total_sim = P_A_sim + P_B_sim` — 주사기 B 내부 전체 압력
- 입자 타입 유지 (혼합 후에도 색상은 보존)
- 타입 간 충돌: 일반 탄성 충돌 (돌턴 법칙 전제: 비반응성)
- 피스톤은 고정, 움직이지 않음 (V_B 불변)

### 5.5 기체 프리셋 (분자량 차이 반영)

| 기체 | 분자량 M | 평균 속도 배율 (1/√M) | 색상 HEX | 질량 비율 |
|---|---|---|---|---|
| 공기 | 29 | 1.00 (기준) | 회색 `#888888` | 1.00 |
| CO₂ | 44 | 0.81 | 초록 `#27AE60` | 1.52 |
| He | 4 | 2.69 | 연빨강 `#E74C3C` | 0.14 |
| N₂ | 28 | 1.02 | 파랑 `#3498DB` | 0.97 |
| O₂ | 32 | 0.95 | 주황 `#E67E22` | 1.10 |

- **속도 배율 적용**: 기체별 평균 속도 = `v_base × (1/√M)` (T=293K 기준)
- **시각 효과**: He는 빠르게, CO₂는 느리게 움직임
- **주사기 A·B 색상**: 학생이 선택한 기체 색상 그대로 사용 (프리셋 색상 유지)
- 단 주사기 라벨에 **"A", "B" 큰 글자** 병기 (색약자 대응)
- 색상 외 **패턴** 옵션 (접근성): 주사기 테두리에 실선/점선 구분

### 5.6 입자 개수 계산

- 기본: `N = k_scale × P × V` (P atm, V mL, k_scale = 2)
- 예: P=1.0 atm, V=100mL → N = 200개
- **최소 보장**: N_min = 20 (입력이 작아도 시뮬 안정성)
- **최대 상한**: 각 주사기 N_max = 300, 중앙 용기 N_max = 600
- 상한 초과 시 자동 다운샘플, 물리 관계는 `N_actual/N_ideal` 비율 보정

### 5.7 입력 검증 및 엣지 케이스

| 상황 | 처리 |
|---|---|
| 슬라이더 빠른 드래그 | 300ms 디바운스 후 재계산 |
| V 너무 작음 (입자 < 20) | N_min=20 강제, 경고 표시 |
| 주입 중 슬라이더 조작 | 애니메이션 중 모든 UI `disabled` |
| 주입 완료 전 `[기록]` 클릭 | 안정화 카운트다운 완료까지 비활성 |
| 단위 토글 중 계산 진행 | 단위는 표시층, 내부 상태 영향 없음 |
| 브라우저 탭 백그라운드 | `requestAnimationFrame` 자동 pause |

## 6. 데이터 흐름

### 6.1 실시간 계산 (매 프레임)

```
1. 시뮬 한 스텝 진행 (60fps)
2. 각 영역 벽 충돌 이벤트 집계
   - 주사기 A: hits_syringe_A
   - 중앙 용기: hits_central_A, hits_central_B
3. 250ms tick마다 압력 계산 (EMA α=0.15):
   - P_syringe_A (주사기 내 압력, 보일 법칙 게이지)
   - P_A^(혼합)_sim = k × hits_central_A / Δt
   - P_B^(혼합)_sim = k × hits_central_B / Δt
   - P_total_sim = P_A^(혼합)_sim + P_B^(혼합)_sim
4. 이론값 계산 (단계별):
   - 단계 1 (A 주입 후): P_total_theory = V_A / V_fixed × 1 atm
   - 단계 2 (B 주입 후): P_total_theory = (V_A + V_B) / V_fixed × 1 atm
5. 실측값 수신 (실센서 모드에서만):
   - WS/Serial로 P_total_measured
6. UI 업데이트:
   - 숫자 라벨 3개 (이론·시뮬·실측)
   - 실시간 그래프 3선
   - 안정화 상태 표시
```

### 6.2 3값 병기 표시 규칙

- 시뮬 모드: **이론 + 시뮬**만 표시
- 실센서 모드: **이론 + 시뮬 + 실측** 모두 표시
- 오차 표시:
  - |시뮬 - 이론| / 이론 > 5% → 노랑 경고
  - |실측 - 이론| / 이론 > 10% → 색상 유지하되 AI 튜터에 "오차 원인 탐구" 질문 생성

### 6.3 이론값 공식 (단계별)

```js
// 단계 1: 초기 상태 (주입 전)
// 주사기 B에 기체 B가 V_B, 1 atm 상태
theory_initial = 1.00;  // atm, 대기압

// 단계 2: 주입 후 (A→B 완전 주입)
// A의 기체가 V_A → V_B 공간에 팽창, B 기체는 그대로
theory_P_A_in_B = (1.0 * V_A) / V_B;   // A의 B 내 부분압력
theory_P_B_in_B = 1.00;                 // B의 원래 압력 유지
theory_P_total = theory_P_A_in_B + theory_P_B_in_B;
                // = (V_A / V_B + 1) * 1 atm

// 예시:
// V_A=100mL, V_B=100mL → P_total = 2.00 atm
// V_A=50mL,  V_B=100mL → P_total = 1.50 atm
// V_A=100mL, V_B=50mL  → P_total = 3.00 atm
```

### 6.4 센서 연동

- **WS 에뮬레이터** (`ws://localhost:8787`): 개발·수업 모두 사용 가능
- **Web Serial**: 실센서 연결 (DFRobot Gravity 1.6MPa)
- 수신 JSON: `{ sensor_name: "DFRobot-1.6MPa", pressure_kpa: 151.2, t_ms: 12345 }`
- 돌턴 페이지에서 **주사기 B 내부 압력**으로 해석
- 주사기 A 에는 센서 없음. 주입 전에는 B 센서값 복사 표시, 주입 후 비표시
- 센서 부착 위치: 주사기 B 실린더 포트 (T자 분기 없이 직접)

## 9. AI 튜터 설계 (심화)

### 9.1 단계 동기화된 Q1~Q4

기존 보일의 Q1~Q4 구조를 확장. **주입 단계와 동기화**하여 맥락 있는 대화.

#### Q1 — 초기 관찰 (실험 시작 시)

- **자동 프롬프트**:
  > "실험 시작. 주사기 A(기체 {gas_A})와 주사기 B(기체 {gas_B})가 있어. 둘 다 대기에서 뽑았다면,
  > 두 주사기의 초기 압력은 같을까 다를까? 왜?"
- **힌트 단계**:
  1. "두 주사기가 어디서 기체를 얻었는지 생각해봐"
  2. "같은 대기라면 같은 압력일까?"
- **목표 이해**: "같은 대기에서 뽑았으므로 초기 P_A = P_B = 1 atm"

#### Q2 — 예측 (주입 전)

- **자동 프롬프트**:
  > "이제 주사기 A의 기체({V_A}mL)를 주사기 B({V_B}mL)로 밀어넣을 거야. **주입 전에 예측**해보자:
  > 주입 후 주사기 B 압력은 얼마일까?"
- **힌트**:
  1. "주사기 A의 기체가 V_A → V_B 공간으로 이동하면, 그 기체의 압력은?"
  2. "주사기 B의 원래 기체는 어떻게 될까?"
  3. "두 부분압력을 어떻게 합칠지 생각해봐"
- **목표**: 돌턴 법칙의 예측적 사용: P_total = (V_A/V_B + 1) × 1 atm
- 예측값을 대화 상태에 저장, Q3에서 실측과 비교

#### Q3 — 검증 + 원리 (주입 후 확인 클릭 시)

- **자동 프롬프트**:
  > "주입 완료. 주사기 B 측정 압력 = `{P_measured}` atm. 네가 예측한 값은 `{user_prediction}` 이었지.
  > 얼마나 맞았어?"
- **후속 질문 (오차 기반 분기)**:
  - 오차 < 2%: "잘 맞았어. 왜 두 기체가 이렇게 독립적으로 압력에 기여할 수 있을까?"
  - 오차 2~10%: "근처네. 차이가 나는 이유를 생각해봐 — 시뮬·실측·이론 중 어디서 오차가 날까?"
  - 오차 > 10% 또는 실센서 모드: "차이가 꽤 나네. 실험에서 이런 오차가 나는 원인을 3가지 이상 떠올려봐"
- **심화 Q**:
  > "만약 A와 B가 화학 반응을 한다면 (예: H₂ + Cl₂ → 2HCl) 돌턴 법칙이 성립할까? 왜?"
  > "만약 주사기 B의 피스톤이 고정 안 돼서 밀려난다면? 압력과 부피는 어떻게 변할까?"

#### Q4 — 실생활 응용

- **선택형 주제** (학생이 고름):
  - (a) **대기권 조성**: "해수면 대기압 1 atm, N₂ 78%, O₂ 21%, Ar 1%. 각 부분압력은?"
  - (b) **고산지대**: "해발 5000m 대기압 0.5 atm. O₂ 부분압력은 해수면의 몇 %? 등산 시 왜 호흡이 힘들까?"
  - (c) **잠수병**: "수심 30m에서 공기 압력 4 atm. 혈중 N₂ 부분압력은? 상승 시 왜 문제?"
  - (d) **자유 질문**
- **목표**: 수업 시연 이후 실생활 응용 연결, 학습 효과 내재화

### 9.2 컨텍스트 주입 포맷

매 메시지 전송 시 시스템 프롬프트:

```
[실험 상태]
- 단계: {A_INJECTED | BOTH_INJECTED | IDLE}
- 주사기 A: 기체 {gas_A_name}, 부피 {V_A}mL, 초기 1 atm
- 주사기 B: 기체 {gas_B_name}, 부피 {V_B}mL, 초기 1 atm
- 중앙 용기: 부피 {V_fixed}mL ({용기크기라벨})
- 현재 측정값 (atm):
  - 이론: {theory}
  - 시뮬: {sim}
  - 실측: {measured} (실센서 모드에서만)
- 학생 기록 최근 3개: {records_json}
- 이 대화에서 학생 응답 요약: {student_summary}

[역할]
너는 고등학교 화학을 가르치는 튜터야. 학생이 돌턴의 부분압력 법칙을 스스로
유도하도록 단계적 힌트를 주고, 정답을 바로 말하지 마. 실험 데이터를 근거로 대화해.
```

### 9.3 보고서 생성 템플릿

- 실험 제목, 조건, 각 회차 측정값
- 이론/실측 비교 그래프 (텍스트 기반)
- 학생 결론 (돌턴 법칙 이해 서술)
- AI 피드백 (이해도 평가)
- PDF·MD 두 포맷 지원 (기존 보일 템플릿 수정)

## 10. UI 세부 동작 규칙

⚠️ 작업자 주의: 본 섹션은 초안(3영역 모델) 기준 서술 그대로. 모델 전환
(§2 결정 6) 이후 용어·버튼 구조가 일부 바뀜. Step B 구현 시 기준은:
- 버튼 구조: §4.2 기준 ([주입 시작]/[확인]/[초기화])
- 주사기 A·B 부피 입력: §4.2 기준 (숫자 입력 전용, 범위 10~100mL,
  기본 50mL. 슬라이더·라디오·프리셋 힌트 없음)
본 섹션의 "[A 주입]", "[B 주입]", "중앙 용기", "라디오", "슬라이더"
같은 표현은 용어 통일 후속 커밋에서 일괄 정리 예정.

### 10.1 슬라이더 변경

- 300ms 디바운스 후 입자 재계산
- 주입 시작 이후는 `disabled`
- 숫자 라벨 즉시 업데이트 (디바운스 전)

### 10.2 `[A 주입]` 버튼

- 상태 `IDLE`에서만 활성
- 클릭 시: `IDLE → INJECTING_A`
- 3초 애니메이션 (슬로모션 영향 없음, 고정 3초)
- 완료: `INJECTING_A → A_INJECTED`
- 자동으로 5초 안정화 카운트다운 시작

### 10.3 `[B 주입]` 버튼

- 상태 `A_INJECTED`에서만 활성
- 흐름: `A_INJECTED → INJECTING_B → BOTH_INJECTED → 안정화 → 기록 가능`

### 10.4 `[초기화]` 버튼

- 상태 무관, 언제든 활성
- 효과: `IDLE` 복귀, 중앙 용기 입자 제거, 주사기 입자 재생성
- 측정 기록 테이블은 **유지** (학생 비교용)
- 그래프: "--- 초기화 ---" 수직 점선 삽입

### 10.5 `[기록]` 버튼

- 안정화 카운트다운 완료 후 활성화
- 클릭 시 현재 상태 스냅샷을 기록 테이블에 append:
  - `회차 | 단계 | V_A | V_B | V_fixed | 모드(시뮬/실센서) | P(이론) | P(시뮬) | P(실측) | 오차%`
- 색상 인코딩:
  - 오차 ≤ 2%: 초록
  - 2~5%: 노랑
  - > 5%: 빨강 (교육 포인트로 유도)

### 10.6 측정 안정화 흐름

```
주입 애니메이션 완료
  ↓
안정화 카운트다운 표시 (5·4·3·2·1)
  ↓ (카운트 진행 중, 그래프 반투명)
카운트 0
  ↓
"안정화 완료 ✓" 표시
  ↓
[기록] 버튼 활성
```

- 카운트다운 중: `[기록]` 버튼 `disabled`, 그래프 반투명
- 카운트다운 완료: 불투명 복귀, 기록 가능
- **학생이 즉시 기록 원할 시**: 안정화 스킵 옵션 (고급 모드 토글, 기본은 엄격)

### 10.7 단위 토글 (atm ⇄ kPa)

- 우상단 버튼, 한 번 클릭으로 전환
- 내부 상태는 항상 Pa (SI), 표시만 변환
- 그래프 y축, 숫자 라벨, 기록 테이블 모두 동시 전환
- CSV 내보내기: **두 단위 모두 컬럼 포함** (연구자·학생 모두 만족)

### 10.8 단계별 이론값 실시간 표시

설정 패널에 작은 정보 박스:

```
┌── 이론값 (실시간 계산) ──┐
│ A만 주입 시: 0.67 atm   │
│ A+B 주입 시: 1.33 atm   │
└────────────────────────┘
```

- V_A, V_B, V_fixed 슬라이더 변경에 따라 즉시 갱신
- 실제 주입 실행 전에도 학생이 **예측 확인** 가능

## 12. 단계별 실행 순서 (Sub-phase 7개)

Phase 5는 **6개 개념 sub-phase + 1개 하드웨어 대기 후속** 으로 쪼갠다. 각 sub-phase는
독립 브랜치를 가지며, **main 에 머지하지 않고 선형 체인**으로 쌓는다. 최종 통합은
Step 3-6 실물 검증 완료 + 모든 sub-phase 종료 이후 **한 번에** main 에 통합.

### 12.0 브랜치 전략

#### 현재 상태 전제

```
main (v0.4, 옛날)
 │
 ├─ phase3-real-sensor        Phase 3 소프트웨어 완료, Step 3-6 실물 검증 대기
 │
 └─ feature/landing-page      최신 커밋 b85fc8f
    (Phase 3 위에 누적 + CAST 브랜딩 + 페이지 분리 + 문서 최신화)
```

**지금은 머지 안 함.** 이유: Step 3-6 실물 검증 전이라 v1.0 태깅 타이밍 부적절.
하드웨어 대기 기간을 활용해 돌턴 Phase 5를 선행 개발.

#### 돌턴 sub-phase 선형 체인

```
feature/landing-page (b85fc8f)
  │
  └─ feature/dalton-shell             [Phase 5.1]  Step A~B
       └─ feature/dalton-sim          [Phase 5.2]  Step C~E
            └─ feature/dalton-data    [Phase 5.3]  Step F~G  ← MVP 완성점
                 └─ feature/dalton-ai           [Phase 5.4]  Step H
                      └─ feature/dalton-polish-partial   [Phase 5.6-a]  문서·반응형
                           ↓ 하드웨어 도착까지 대기
                           ↓ (Step 3-6 완료 후)
                           └─ feature/dalton-sensor        [Phase 5.5]  Step I
                                └─ feature/dalton-polish-final  [Phase 5.6-b]  실센서 마감
```

#### 핵심 원칙

1. **각 sub-phase는 이전 sub-phase 위에서 분기** (head of previous branch)
2. **이전 브랜치는 삭제하지 않음** — 히스토리 점으로 보존
3. **각 sub-phase 완료 시 태그 부착**: `phase5.1-complete`, `phase5.2-complete`, …
4. **원격 push 는 sub-phase 완료 시점마다** (중간 커밋은 로컬 push 자유)
5. **main 머지는 먼 미래** — 전체 작업 종료 후 한 번에 대규모 통합

#### 하드웨어 도착 전/후 구분

| Sub-phase | 하드웨어 필요 | 비고 |
|---|---|---|
| 5.1 shell | ❌ | DOM만 |
| 5.2 sim | ❌ | p5.js |
| 5.3 data (MVP) | ❌ | 시뮬 계산 |
| 5.4 ai | ❌ | API만 |
| 5.6-a polish-partial | ❌ | 문서·반응형·기획 스크린샷 |
| **5.5 sensor** | ⚠️ 실물 | Step 3-6 선행 필요 |
| 5.6-b polish-final | ⚠️ 실물 | 실센서 스크린샷·BOM·수업 문서 |

대기 기간에 **5.1 → 5.2 → 5.3 → 5.4 → 5.6-a** 까지 진행 가능.

```bash
# 1) main 기준 최신화

#   대규모 rebase, 충돌 여러 곳 가능 — 신중히
git checkout main
git merge feature/dalton-polish-final
git tag v1.1 -m "Phase 5 돌턴 실험 완성"

git branch -d feature/landing-page feature/dalton-shell feature/dalton-sim \
              feature/dalton-data feature/dalton-ai \
              feature/dalton-polish-partial feature/dalton-sensor \
              feature/dalton-polish-final
```

#### 통합 시점 주의

- **rebase 충돌 집중 발생 가능 지점**: `docs/10-dev-journal.md`, `web/js/ui.js`
- `ui.js` 는 거의 전 sub-phase 에서 수정되므로 rebase 시 충돌 누적
- **권장**: 통합 전 하루 정도 여유 두고 별도 세션에서 rebase 전용 작업

#### 통합 대안: Merge commits 유지

rebase 대신 순수 merge 쓰면 히스토리 복잡해지지만 rebase 충돌 부담 감소. 
개인 repo 기준 **Merge commits 방식도 수용 가능**. 최종 결정은 통합 시점에 판단.
